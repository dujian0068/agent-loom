# 验收与审查

先读取需求及方案，核对事实来源。每项已确认需求至少对应一个可观察结果；“正确处理”“符合要求”不能独立充当预期结果。

用例明确前置条件、操作和预期；并发用例写明请求如何竞争及允许的最终状态。未确认规则只能写条件式用例并标记“待确认”，不能擅自替业务决策。

审查报告记录问题位置、影响、依据和建议；没有发现问题也说明已检查范围。只修改分配给自己的输出文件，不改写其他执行器的文档。

读取 `assets/acceptance-template.md` 生成验收文档。审查结果是文档检查，不是实际软件用例已执行通过的证明。
