# 需求评审

先读取任务输入，并按需检索已授权知识库。为已确定规则编号 R01、R02 等；来源写成用户输入或具体文档名称和章节，不编造引用。

分别记录业务事实、方案建议和待确认事项。未确定的业务策略不得写成既定要求。除非缺失信息阻止所有工作，否则先完成不依赖该信息的部分。

检查角色及对象权限、状态变化、并发冲突、重复请求、失败回滚、时间边界。会议预约应检查相邻区间、跨日、时区、精确两小时和取消后的占用释放；未提供规则时列为问题，不擅自决定。

读取 `assets/requirements-template.md` 作为交付结构，按任务指定路径写文件。保留需求编号供后续方案和验收引用。
