# 方案概要

读取需求文件，引用需求编号区分“已确认规则”与“建议实现”。按系统职责拆模块，不把每个页面当成一个服务，也不默认引入分布式基础设施。

说明关键对象、状态、接口行为及错误情况。涉及竞争的约束必须说明服务端如何原子保证，不能仅依赖前端检查。例如预约冲突需讨论并发事务中的校验和约束，而不只画查询流程。

未确认业务规则用配置点或待定项描述。先读取 `assets/solution-template.md`，按任务路径交付；不把方案草案称为已实现的软件。
