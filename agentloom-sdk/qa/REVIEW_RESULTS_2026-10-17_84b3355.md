### R3-01：关闭超时不能成为重执行业务的理由

**复现 A：MCP。** 让 `call_tool` 立即返回包含 `ALREADY_COMPLETED` 的已知结果，只有会话退出等待 1.2 秒；配置 `tool_timeout_seconds=1`，开启最多 2 次重试、间隔为 0。内存和文件后端、`isError=false/true` 四种组合均复现：

```text
call_tool 实际调用次数 = 2
Attempt 数 = 2
最终工具错误 = TOOL_TIMEOUT
result = null
execution_fact = unknown
```

业务在第一次调用时已经完成，关闭连接的超时却被当成执行超时。这会给有副作用的 MCP 工具带来重复操作风险。关闭立即完成的四个对照均通过；本测试未调用真实外部业务系统。

**复现 B：模型。** 模型先返回合法 completed 和完整文本，再在流关闭阶段等待。此时调用 `stop()`，Run 正确变为 cancelled，用户没有收到成功答案，但已取得的完整材料被丢弃：`op.raw=null`，最终响应的执行事实为 unknown。两种后端均复现。期望停止仍生效，同时保留已完成响应及其真实执行事实。

**原因与位置：** [resources.py:33](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/resources.py:33) 在关闭遇到 CancelledError 时重新抛出；[mcp.py:112](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/capabilities/mcp.py:112) 的业务结果尚未越过上下文退出边界，[handlers.py:120](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/runtime/handlers.py:120) 也在返回完整响应前等待 aclose。调用驱动因此只看到超时或取消，没有已取得结果的证据。

**验收要求：** 在关闭连接前固定已知业务结果／错误，关闭失败与业务结果分别记录；单纯关闭超时不得新增物理调用。根 stop、deadline、失权仍必须生效，不能通过吞掉取消或失权来“修复”。具备有效租约时应保存已收到的完成材料，失权时仍拒绝旧 owner 提交。依据：[能力调用与完成合同](/Users/bmilk/code/project/agent-loom/docs/sdk/capabilities.md:62)、[控制期间保留已取得事实](/Users/bmilk/code/project/agent-loom/docs/sdk/runtime.md:433)。

测试入口：[MCP 完成后关闭超时](/Users/bmilk/code/project/agent-loom/agentloom-sdk/qa/test_sdk_review_round3.py:117)、[模型完成后关闭期间停止](/Users/bmilk/code/project/agent-loom/agentloom-sdk/qa/test_sdk_review_round3.py:144)。

### R3-02：usage 事件的已知计数被丢弃

**复现：** 自定义 ModelAdapter 先发送文档支持的 `ProviderEvent("usage", {"input_tokens":3,"output_tokens":2})`，再发送 completed：

| completed 中的 usage | 期望累计 | 实际累计 |
| --- | --- | --- |
| null | `(3, 2)` | `(null, null)` |
| `{}` | `(3, 2)` | `(null, null)` |
| `{"input_tokens":null,"output_tokens":5}` | `(3, 5)` | `(null, 5)` |
| `{"input_tokens":9,"output_tokens":5}` | `(9, 5)` | `(9, 5)`，正常对照 |

前三种情况在两后端产生 6 个失败。另将 usage 事件的输入计数改为 `2**53`、completed 不附统计，两后端仍返回 succeeded，未拒绝超出规范 JSON 整数范围的计数；负数和布尔值对照能正确拒绝。

**原因与位置：** [handlers.py:97](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/runtime/handlers.py:97) 仅验证 usage 事件，没有按 Attempt 保存并与 completed 合并；[material.py:28](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/models/material.py:28) 只校验类型和非负，没有校验安全整数上界。最终汇总只读 completed 的 usage。

**验收要求：** 通用模型边界按字段保留最近已知计数，null／缺字段不擦除已知值，0 合法；usage 事件和 completed 使用相同的安全整数约束，越界返回 `MODEL_PROTOCOL_ERROR`。依据：[usage 与计数范围合同](/Users/bmilk/code/project/agent-loom/docs/sdk/capabilities.md:40)。

这与上轮 Chat SSE 的 R02 是不同入口。Chat 的空 usage 修复已通过；本项影响使用公开 ProviderEvent 接口的自定义模型适配器，未声称内置 Chat 原场景再次失败，也未观察到本项污染存储。

测试入口：[usage 合并](/Users/bmilk/code/project/agent-loom/agentloom-sdk/qa/test_sdk_review_round3.py:187)、[usage 事件整数边界](/Users/bmilk/code/project/agent-loom/agentloom-sdk/qa/test_sdk_review_round3.py:211)。

### R3-03：函数已经返回，非法结果却记为执行未知

**复现：** 使用 `FunctionToolAdapter` 包装一个正常执行一次后返回 `float("nan")` 的函数。运行结束后，工具失败记录为：

```text
code = INVALID_JSON
category = business
external_outcome = known
execution_fact = unknown
```

返回值非法，应作为协议结果拒绝，但“函数已经正常返回”的事实仍应保存。原生 `invoke_once` 返回含相同非法值的 JSON 信封时，可以正确保存 `execution_fact=completed` 和 protocol 分类，两个对照均通过。未观察到自动重试或重复函数调用。

**原因与位置：** [contracts.py:141](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/capabilities/contracts.py:141) 在底层函数返回后调用 `ToolResult.from_value`；其冻结校验抛出的异常发生在 [invocation.py:39](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/capabilities/invocation.py:39) 的完成事实保护范围之外。旧 invoke 兼容分支也在该保护范围之前包装结果。

**验收要求：** 区分“适配器执行中抛错”和“适配器已返回但结果非法”，让值返回桥接层与原生返回路径使用一致的协议分类和完成事实；不能把所有适配器异常都直接标成 completed。依据：[能力结果校验合同](/Users/bmilk/code/project/agent-loom/docs/sdk/capabilities.md:105)。

测试入口：[非法值返回的执行事实](/Users/bmilk/code/project/agent-loom/agentloom-sdk/qa/test_sdk_review_round3.py:229)。

### R3-04：超大锁等待参数未归一为配置错误

**复现：** 分别将 `10**1000`、`-(10**1000)` 传给 `RuntimeProperties(store_lock_timeout_seconds=...)` 和 `FileRuntimeStore(lock_timeout_s=...)`。四种组合均直接抛出 `OverflowError: int too large to convert to float`，而非 `ConfigurationError / STORE_LOCK_TIMEOUT_INVALID`。

**原因与位置：** [properties.py:26](/Users/bmilk/code/project/agent-loom/agentloom-sdk/src/agentloom/configuration/properties.py:26) 的 `math.isfinite` 先隐式转换超大整数，校验本身就发生溢出。该问题限于错误归一；未创建运行记录，也未观察到存储污染。

**验收要求：** 先安全处理数值范围／转换异常，两个入口一致返回配置错误。null、布尔值、NaN、正无穷和普通负数当前均能正确拒绝；0 当前能正确接受。这些对照应继续保留。

测试入口：[存储等待参数边界](/Users/bmilk/code/project/agent-loom/agentloom-sdk/qa/test_sdk_review_round3.py:265)。
