# Platform 首版交互设计

这是一版面向团队私有部署的交互提案，配合[实施方案](implementation-plan.md)评审。它定义首版页面、操作反馈和异常处理，尚未代表已实现的前端。平台现有目录仍是骨架；可点击原型使用示例数据，不连接模型或真实后端。

[打开可点击原型](https://doc.agentloom.bmilk.cn/prototypes/platform-interaction/) · [查看原型源码与维护说明](../../agentloom-platform/web/prototypes/README.md)

首版围绕两条路径组织：编辑者把应用配置成可发布的版本，成员用已发布应用完成自己的任务。应用在空间内共享，会话默认只属于创建者。

## 1. 信息架构与导航

```text
登录
└─ 空间（有多个可访问空间时显示切换器）
   ├─ 应用
   │  ├─ 应用列表 → 新建应用
   │  └─ 应用
   │     ├─ 使用 → 我的会话 → 会话工作台 → 运行详情
   │     ├─ 配置 → 草稿 → 校验 → 发布确认
   │     └─ 发布记录 → 版本详情 / 发布任务
   ├─ 我的会话（仅当前空间、当前用户）
   ├─ 资源（编辑者可选用，管理员维护）
   └─ 空间管理（管理员）
      ├─ 成员与角色
      ├─ 运行与发布任务
      └─ 审计记录
```

左侧导航只放跨应用入口；应用内部采用「使用／配置／发布记录」导航。切换应用前保留未提交的编辑内容；切换空间后重新加载授权范围，不沿用上个空间的列表、会话或资源。

| 页面 | 建议前端路径 | 主要任务 |
| --- | --- | --- |
| 应用列表 | `/s/:space_id/apps` | 找到可用应用；编辑者创建、配置应用 |
| 草稿编辑器 | `/s/:space_id/apps/:app_id/config` | 保存、校验和发布草稿 |
| 发布记录／任务 | `/s/:space_id/apps/:app_id/releases/:release_id` | 了解版本内容、发布阶段和失败原因 |
| 我的会话 | `/s/:space_id/sessions` | 继续自己的历史任务，按应用筛选 |
| 会话工作台 | `/s/:space_id/apps/:app_id/sessions/:session_id` | 提问、补充、停止、阅读结果 |
| 运行详情 | `/s/:space_id/runs/:run_id` | 查看公开进度、版本和诊断信息 |
| 资源／空间管理 | `/s/:space_id/resources`、`/s/:space_id/settings` | 管理固定资源版本、成员与审计 |

以上是前端路由建议，HTTP API 仍以 [API 设计](api.md)为准。运行详情可以从工作台打开侧栏，但也有独立地址，便于刷新和定位。

## 2. 权限如何体现在界面上

| 操作 | viewer（使用者） | editor（编辑者） | admin（管理员） |
| --- | --- | --- | --- |
| 使用已发布应用，查看、补充或停止自己的会话 | ✓ | ✓ | ✓ |
| 创建应用、编辑草稿、校验、发布 | — | ✓ | ✓ |
| 读取可选资源的名称、版本、可用状态 | — | ✓ | ✓ |
| 管理模型凭据、导入资源、管理成员 | — | — | ✓ |
| 查看或停止其他成员的运行 | — | — | 显式进入管理入口，记录审计 |
| 删除应用及其专属数据 | — | — | SDK 完整清理能力就绪后开放 |

无权限的导航和常规操作不显示；因前置条件未满足而暂不可用的操作保留并说明原因。例如 viewer 不显示「配置」，编辑者能看到但不能点击「发布」，旁边提示「请先保存并通过校验」。前端可见性不替代后端鉴权。

管理员的「我的会话」仍只显示自己的历史。跨用户查看必须从「空间管理 → 运行与发布任务」进入，填写查看理由后留下审计；不把所有人的聊天混在普通会话列表。编辑者发布时可看到将受影响的运行数量，但不能借此读取其他用户的内容。

## 3. 应用列表与创建

应用列表展示名称、应用描述、模式、当前发布版本和可用状态。编辑者看到已保存草稿中的描述，使用者看到当前发布版本的描述；没有描述时显示「未填写应用描述」。编辑者额外看到「有未发布修改」及发布任务状态；不使用运行次数、成功率等尚未定义口径的指标填充首页。

| 应用状态 | 使用者看到 | 编辑者主操作 |
| --- | --- | --- |
| 尚未发布 | 不出现在可用应用列表 | 配置应用 |
| 可用 | 使用应用 | 使用应用；编辑草稿为次操作 |
| 发布中 | 暂停新输入，可查看自己的历史 | 查看发布进度 |
| 发布失败且接入仍关闭 | 暂不可用，可查看历史 | 查看失败阶段；由有权限者重试 |
| 删除中 | 暂不可用，可查看允许保留的删除进度 | 查看删除进度 |

创建表单按「应用名称 → 应用描述 → 执行模式」排列：

| 字段 | 输入与约束 |
| --- | --- |
| 应用名称 | 必填，去除首尾空白后 1–100 字 |
| 应用描述 | 选填，多行文本，最多 2000 字；说明应用用途、适用场景和预期结果，创建后可继续修改 |
| 执行模式 | 选择 ReAct 或 Plan，创建后不可更改 |

名称和描述随创建请求写入初始草稿，进入配置页后回填。描述用于应用列表展示，修改后需保存；发布时固定到候选版本，成功发布后对使用者生效。描述为空不阻止创建或发布，也不会用「未发布」等状态文案代替用户描述。

模式选项用任务语言解释：

- **ReAct**：一个 Agent 连续推理并调用工具，适合一般问答和工具任务。
- **Plan**：先组织计划，再交给配置的专业执行器，适合分工任务。

模式旁持续显示「创建后不可更改」。提交创建后直接进入草稿编辑器；未配置模型或没有可用资源时，给出具体缺项。编辑者可联系管理员配置模型，管理员有对应入口。首版不提供 Workflow 画布。

## 4. 草稿编辑器

桌面采用分组表单；页头始终区分「当前发布 v3」与「正在编辑草稿 r8」。表单顶部显示保存状态，底部或页头提供一个主要动作：未保存时为「保存草稿」，已保存待校验时为「校验配置」，校验通过后为「发布…」。其余动作以次要按钮呈现。

| 分组 | 内容与交互 |
| --- | --- |
| 基本信息 | 名称、应用描述、只读模式；描述可编辑，参与保存、未保存离开确认及发布快照 |
| 模型与提示词 | 从已授权模型连接中选择；编辑系统提示词；上下文与输出上限显示明确单位，K 按 1024 换算 |
| 能力 | 选择固定版本的 Tool、Skill、MCP 成员和函数 Hook；显示名称、版本、可用状态 |
| 执行限制 | 按 SDK 已有能力填写预算与限制；区分默认值和显式覆盖 |
| 专业执行器 | 仅 Plan 显示；填写标识、职责和能力范围；校验标识重复、缺少职责等错误 |

Executor 属于当前应用，不提供独立发布或聊天入口。当前模型与策略共享约束在表单中说明，不提供实际上不生效的独立模型选项。Skill 脚本执行默认不开放，资源已导入不等于其中任意脚本可执行。

**保存与冲突：**首版显式保存，不把本地输入自动当成已保存。成功后更新 revision 和保存时间；失败保留编辑内容。收到 409 时，在当前页展示「草稿已被另一位成员更新」，提供「比较差异」和「载入最新草稿」。差异页显示我的编辑与最新版本，用户逐项确认后基于最新 revision 再保存；没有强制覆盖按钮。离开未保存页面时提供「保存后离开／放弃修改／继续编辑」，浏览器关闭使用原生未保存提示。

**校验：**只校验已保存 revision；校验期间可继续阅读。任意配置变更会使旧校验结果失效。错误在页顶汇总，并在对应字段旁显示可操作信息；点击错误跳到字段。资源不可用要带资源名称与版本。基础设施暂不可用与配置错误分开显示，避免让用户反复修改正确配置。校验通过也不代表已经调用过真实模型。

**发布入口：**只有已保存且校验通过的 revision 可发布。按钮写「发布…」，随后展示将固定的候选版本。草稿没有「试运行」按钮；验证实际效果需先发布，再从「使用」进入自己的会话。

## 5. 发布确认与进度

发布确认页展示：候选版本、来源草稿 revision、模型／提示词／资源等变更摘要，以及影响范围。首次发布明确「发布后空间成员可使用」；更新发布明确写出「将停止旧配置上的 N 个活动任务」，并说明发布期间暂停新提问与补充输入，停止和历史查询仍可用。

主按钮使用完整文案「停止相关任务并发布 v4」；没有受影响任务时用「发布 v4」。数量带检查时间，确认时服务端重新检查；若影响范围变化到超出用户看到的确认信息，刷新确认内容，要求再次确认。不可通过静态数量保证后台没有新增任务。

```mermaid
flowchart LR
    A["保存并校验草稿"] --> B["查看变更与影响"]
    B --> C["确认发布"]
    C --> D["暂停新输入"]
    D --> E["停止旧任务并完成清理"]
    E --> F["启用新版本"]
    F --> G["新问题使用新版本"]
```

确认返回持久发布任务后进入进度页；不用一条短暂 toast 表示发布已经成功。步骤采用有依据的阶段，不显示虚构百分比：

| 后台阶段 | 页面文案 | 可用操作 |
| --- | --- | --- |
| prepared | 已准备候选版本，正在暂停新输入 | 查看候选版本 |
| stopping | 正在停止旧版本任务 | 查看已授权任务、返回应用 |
| waiting_cleanup | 等待运行清理完成 | 查看诊断；保留历史查询 |
| activating | 正在启用新版本 | 查看候选版本 |
| succeeded | v4 已发布 | 使用应用、查看版本 |
| failed | 发布失败，停在具体阶段 | 查看原因；管理员重试原发布任务 |

刷新、切换页面或断线后，从同一任务恢复展示，不重新创建发布。关闭进度页不取消发布。首版不提供已启动发布的取消或隐式回滚；失败时保持接入状态可见，重试继续固定候选版本。若需要恢复旧配置，后续必须设计成一次显式发布，不能把切换版本伪装成普通编辑。

发布开始后可编辑下一份草稿，但候选版本内容锁定，页面提示「这些修改不包含在正在发布的 v4 中」。会话中的已完成回答保留原版本标签，新问题才使用新的当前版本。

## 6. 会话工作台

主区域放用户消息与最终答案，过程区域默认折叠，执行时可展开查看公开进度。页头显示应用、当前会话和「仅自己可见」。正在执行的任务显示它实际使用的版本；若应用已更新，另提示「下一次提问将使用 v4」，不能直接改掉历史任务的版本。

### 输入与按钮

| 当前情况 | 输入框说明／主按钮 | 行为 |
| --- | --- | --- |
| 空会话或上一轮结束 | 「输入问题」／发送 | 创建新一轮；先显示本地发送中，平台确认后才显示已保存 |
| 任务执行中 | 「补充本轮要求」／发送补充 | 进入同一任务；Plan 补充只交给 Planner |
| 正在停止 | 「填写下一轮问题，停止后再发送」／暂不可发送 | 保留本地文本；收到终态后由用户点击发送，不自动启动 |
| 发布或删除阻止新输入 | 显示暂停原因／暂不可发送 | 保留本地文本；历史与停止仍可用 |
| 发送结果未知 | 同一条消息显示「正在确认是否送达」 | 使用原请求身份查询或重试，不新增气泡 |

补充区只支持当前 SDK 的文本补充，不出现附件、变量覆写或执行器选择。普通新问题按已定义输入能力提供表单；尚未接入的附件内容服务不显示可用上传按钮。

文本输入采用 Enter 发送、Shift+Enter 换行，中文输入法合成期间不触发发送；按钮始终可用作替代。发送后只清空已经被平台确认保存的文本。明确未接收的失败可以修改后重新发送；回执未知的失败先确认原提交，避免产生重复任务。

### 消息送达状态

| 状态 | 用户文案 | 不能推断的事 |
| --- | --- | --- |
| 浏览器正在提交 | 正在提交 | 不表示平台或模型已经接收 |
| 平台已持久保存，SDK 未确认 | 已保存，等待接收 | 不显示「模型正在处理」 |
| SDK 已确认初始输入 | 已接收 | 不代表已完成第一轮模型调用 |
| SDK 已确认补充、尚未消费 | 补充已接收，等待本轮采用 | 不显示「已采用」 |
| 补充已消费 | 本轮已采用 | 依据查询的实际投递状态显示 |
| pending_next_run | 待下轮生效 | 不自动创建下一轮，不要求用户重复发送 |
| 明确拒绝 | 未接收：具体原因 | 不把被拒绝内容并入模型上下文 |

「待下轮生效」紧邻原补充消息显示，并在输入框上方汇总未采用条数。下一次由用户主动发起的新问题携带这些输入，成功消费后更新原消息状态。用户仍可直接继续提问；首版不虚构撤回、编辑或删除待交接补充的能力。

### 运行与结果

公开过程展示阶段、工具名称及经过白名单投影的状态，隐藏模型内部推理、原始审计内容和执行器内部材料。Plan 可以展示专业执行器的任务名称及状态，但子任务完成不冒充整轮完成。

本版不承诺 token 流式输出。等待时显示公开阶段与连接状态，不播放逐字生成的假答案；收到最终终态后查询完整结果，再将最终答案放入回答区域。

| 状态 | 反馈与操作 |
| --- | --- |
| 等待接收 | 展示已保存回执及等待状态；可提出停止请求 |
| 执行中 | 展示公开进度；提供发送补充和停止 |
| 停止中 | 「已请求停止，正在等待任务结束」；重复点击不生成新控制意图 |
| 已停止 | 保留已有可展示进度；有未消费补充时标为待下轮生效 |
| 已完成 | 展示最终答案、实际版本和可用用量；允许下一次提问 |
| 执行失败 | 展示可公开的原因；保留原输入和进度，用户主动重新提问才建立新任务 |
| 机器故障恢复中 | 显示最后确认状态与更新时间；系统自动接续原任务，用户没有恢复按钮 |
| 连接中断 | 「连接已断开，任务可能仍在继续」；自动重连并补齐状态，不改成执行失败 |

点击「停止」直接提交停止意图，无需二次确认；它不是立即终止的承诺。关闭浏览器、离开会话或断开连接均不停止后台任务。

执行终态与清理状态分别展示。结果已完成但清理失败时，答案保持可读，旁边显示「结果已保存，后台清理需要处理」；管理员在诊断页重试清理。不能把清理故障显示成「回答失败」或成功删除。

## 7. 资源与空间管理

资源列表按模型连接、Tool、Skill、MCP、函数 Hook 分类。列表显示固定版本、可用状态和引用情况；编辑者只能查看可选元数据，管理员才能修改凭据、导入和停用。删除或停用被发布版本引用的资源前展示影响，不破坏旧任务恢复所需依赖。

模型连接表单分离名称、供应商、地址、凭据与明确的能力上限。已保存凭据只显示「已设置」，不回填明文；替换凭据是独立动作。保存成功与连接测试成功分开标记，未实现测试接口时不提供虚假的「连接正常」。

MCP 由管理员显式发现，选择本次要暴露的成员，再固定其 schema 和版本；不在用户每次打开编辑器时自动扫描远端。资源导入失败保留失败原因和可重试任务，不能让未完成的版本出现在可选列表。

成员列表显示用户名与空间角色，角色修改、移除成员有明确确认和审计。撤销权限后，已打开页面停止接收受保护信息并清空对应内容；返回空间选择或无权限页，不继续依靠旧缓存。服务端同时处理已接收工作的停止，界面不声称撤权已瞬间中止所有执行。

管理员运行列表将业务状态、清理状态和最后观测时间分列，能定位停止未完成、发布阻塞和清理失败。诊断详情与普通最终答案分开，凭据和内部推理不进入用户界面。

## 8. 删除及尚未开放的能力

当前 SDK 缺少完整的会话级删除合同，内部预览仅展示禁用的「删除应用」及原因；viewer 和 editor 不显示这个入口。不能以归档代替彻底删除，也不能返回成功删除提示。

能力就绪后，管理员在危险操作区看到删除范围：应用、发布、会话、Run 及应用专属文件；共享模型、Tool、Skill 等资源保留。输入应用名称确认后，进入持久删除任务：关闭接入 → 停止运行 → 清理会话及待交接输入 → 清理专属文件 → 删除平台关联。每一步可恢复，失败停在实际阶段；清理完成前不从管理视图移除记录。

首版界面不开放用户暂停／恢复、Workflow 画布、任意代码上传执行、附件知识库、跨用户共享会话和 token 流式输出。这些能力单独设计后再增加入口。

## 9. 通用反馈、响应式与可访问性

| 场景 | 交互约定 |
| --- | --- |
| 登录过期（401） | 跳登录，保留安全的返回地址；不把提示词、凭据写入 URL |
| 不可见对象（404） | 「内容不存在或你无权访问」，不泄露名称和归属 |
| 无操作权限（403） | 保留仍可访问的页面，更新权限与操作入口 |
| 草稿或请求冲突（409） | 区分编辑冲突和重复请求正文冲突；后者查询原提交，不静默换键 |
| 缺少版本条件（428） | 刷新版本后再操作；不降级为无条件保存 |
| 配置错误（422） | 字段旁错误＋顶部汇总，保留输入 |
| 基础设施异常（503） | 显示最后确认状态、观测时间和重试入口；不伪造终态 |
| 空列表／加载失败 | 分别展示空态行动和失败重试，不能把错误渲染成「暂无数据」 |

关键状态常驻页面，toast 仅用于保存等低风险反馈。状态用文字与图形共同表达，不只靠颜色；错误摘要用 `role="alert"`，异步阶段用克制的 `aria-live` 更新。

桌面宽屏可同时显示会话与过程侧栏，较窄时把过程改为消息后的折叠区域。移动端将空间导航收进可访问菜单，编辑表单单列、动作换行；确认框占可用宽度。完整内容不依赖 hover，不靠横向滚动阅读普通表单和会话。

所有字段有标签；模式、版本、状态也有文本。按钮键盘可达，模态框正确管理焦点，Escape 关闭尚未确认的弹窗，关闭后焦点回到触发按钮；异步更新不夺取输入框焦点。确认后的发布任务属于独立状态页，不因 Escape 而取消。

## 10. 原型范围与验收

可点击原型重点覆盖：应用到配置／使用的分流、ReAct 与 Plan 表单差异、保存后校验、发布影响确认与阶段、会话补充和停止、待下轮提示。资源与成员页只演示信息布局；网页顶部的「原型预览设置」可以切换角色、连接状态、过程布局和异常场景。原型反馈均为本地模拟，刷新会重置模拟应用与运行，不能作为 API 或 SDK 的验证结果。

生产实现至少验收以下交互，工程阶段与[实施方案](implementation-plan.md#实施顺序和验收门槛)对应：

| 阶段 | 必须跑通的用户路径 |
| --- | --- |
| P1 | 管理员添加成员与模型连接；编辑者创建 ReAct、保存校验、首次发布；两名成员独立会话且无法读取对方内容 |
| P1 | 表单错误保留输入；双击发送不重复；刷新能恢复已提交任务；重连补齐进度；完整答案仅展示一次 |
| P2 | Plan 专业执行器配置；运行中补充；停止前后输入竞态；待下轮内容不重复发送且不自动开新任务 |
| P2 | 两人同时编辑出现可解决冲突；更新发布展示影响、阻止新输入、可离页恢复；后续草稿不改变候选版本 |
| P2 | 发布失败保留接入状态和诊断；角色撤销后旧页面与推送失效；管理员跨用户操作留下审计 |
| P3 | 完成但清理失败仍能阅读答案；删除前准确展示范围、失败可恢复、共享资源保留；键盘和窄屏路径可完成 |

这版确定页面和操作合同；生产样式、设计组件库、真实接口联调与权限端到端测试在前端实现时完成。
