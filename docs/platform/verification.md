# 平台验收计划

本页是待实施的 API 验收，不是已通过报告。SDK 自身验收见 [SDK 验证矩阵](../sdk/verification.md)。

| 场景 | 必须断言 |
| --- | --- |
| 管理权限 | 空间成员与会话可见性分别检查；无权请求不创建分派 |
| 固定模式 | ReAct / Plan 模式创建后不可变；ReAct 无 Executor 配置 |
| 草稿和发布 | 草稿不能运行；发布校验定位缺少资源和输入错误 |
| 资源解析 | 平台在构造前解析全部资源和 Workflow Agent 依赖 |
| SDK 独立边界 | 断开平台目录查询后，已构造 Agent 可完成执行；SDK 无平台实体必填字段 |
| 版本固定 | 原 Run 恢复用原配置，下一次新提问用当前发布配置 |
| 发布屏障 | 发布扫描包含直接 Run 和 Workflow 引用；晚到旧分派不启动新工作 |
| 请求重试 | HTTP 回执丢失，重投同逻辑请求不重复 Run／用户输入 |
| 进程恢复 | SDK 已接收、平台未记回执时故障，另一 Worker 重投同 Run 继续 |
| 补充竞态 | SDK 接收与 Run 结束竞争，输入明确 pending／delivered／carried 或成为新提问，不丢不重 |
| Plan 补充 | 只进入 Planner 下一轮，不广播 Executor |
| SSE 续读 | 单调事件序号、去重和终态；断开连接不停止执行 |
| 结束 | 用户 stop 被持久接收；无 Worker 时也可终结；不提供用户暂停／恢复按钮 |
| 删除 | 先收束再清理专属记录／文件，保留共享资源，失败可重试 |
| 分库部署 | 平台管理库与 SDK 执行存储分开仍可通过接入、补充、停止和恢复 |
| 真实模型 | 在测试空间配置凭据后通过 HTTP API 跑 ReAct、Plan 和 Workflow；不以页面观察代替断言 |

测试应报告请求、回执、SDK run_id、事件序列、终态和文件／调用证据。确定性适配器、真实存储故障注入和真实模型分别标记，不把文档链接检查或模拟模型成功算作全链路通过。

补充交接断言：Worker 已通过平台 gate、尚未初始化 SDK 时并发发布／删除。SDK stop 必须先保存该 run_id 的 admission 关闭标记；迟到 ainvoke 返回 RUN_ADMISSION_CLOSED，不出网、不创建执行域。
