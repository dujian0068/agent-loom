# 本机执行验收 · 2026-11-03

本机执行实现和部署方式见 [exec 说明](host-exec.md)。应用默认关闭命令执行；启用后仍须为角色显式绑定 `exec`，不需要启用沙箱。

## 本机验证

- 后端完整回归 **96 通过、1 跳过**；跳过项为本机 LibreSSL 缺少的证书域名预检。Ruff 通过。
- 前端 **29 通过**，TypeScript 与生产构建通过。覆盖执行服务不可用时禁用选项、开启本机执行后才能选择 `exec`、保存执行设置与角色绑定。
- 真实进程验证 Python 执行、工作区文件、退出码、标准输出／错误、超量输出截断、超时、取消、断开连接、后台进程组清理及干净命令环境。
- 执行服务拒绝错误 Worker 身份、越界／符号链接工作空间和不一致的实现版本。
- 本机模型 HTTP 服务、真实 Worker 子进程、独立执行服务验证 ReAct／Plan 私有草稿调用命令。Plan 的执行器通过文件工具读取前一步命令产物。
- API 停止时先确认命令进程组结束再结算工具回执；Worker 被 SIGKILL 后连接断开，命令被终止，恢复时保留未知结果并阻止重放。
- 从带历史数据的旧数据库升级到 `0003`，原 `exec` v1 不变，追加可用 v2；重复迁移不重复创建版本。历史会话、任务、输入和外键完整。

浏览器使用独立临时账号与测试模型：在「运行环境」选择本机执行，在「能力配置」授权 `exec`，从右侧发送任务自动保存为 r2。实际执行 Python 写入 `exec.txt`，数据库中的工具回执包含 `EXEC_OK`，物理文件内容为 `host-exec-verified`；页面显示模型 2 次、工具 1 次、`exec` 成功。

## 验收边界

上述本机进程测试使用显式测试启动参数，以当前开发账号运行独立执行进程，不代表生产低权限账号已验收。生产安装脚本默认禁止 root 或与 Worker 相同 UID 运行服务；脚本另有真实 UID、共享文件权限和环境检查。a2 的账号及系统服务安装需要 sudo，生产启用与模型联调结果另行记录，未启用前不能宣称线上命令执行可用。
